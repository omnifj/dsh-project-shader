## 技术方案

### 架构约束（保持不变）

- 渲染仍全部在 `client.js`（`window.__ModuleLoader__` 工厂），Host 半身为空 `apply()`
- CSS 仍挂在 `shell.overlay` 的单个 `<style>`；状态着色只新增规则，不改挂载方式
- 存储键 `dsh-project-shader:settings:v2` 不变；新增键走既有 `normalizeGlobal` 白名单，旧数据无损
- `useSessionStatus` 为 `shell.overlay` 标准 props（`SnapshotSelectorHook<ReadonlyMap<SessionId, SessionStatus>>`），快照缺失时降级为不着色

### 关键设计

- **状态着色优先级**：等待输入 > 运行中 > 完成未读；运行中用 `@keyframes` + CSS 变量 `--dsh-ps-c` 做呼吸光环，等待/未读用主题语义 token（warn/success）
- **OKLCH**：sRGB↔线性↔LMS↔OKLCH 矩阵换算，明度抬向 0.74·k、彩度 ×(1+0.8k)，二分退火钳回 sRGB 色域；`C<0.03` 的灰色只提亮不染彩
- **品牌色**：`{ id:'brand', value:'var(--dsw-alias-brand-primary)' }` 作为自动配色首槽；`var()` 色跳过 OKLCH 变换与文字补偿，辉光用 `color-mix` 直接混合
- **强调覆盖**：只作用于渲染层（`buildCss`），不改动自动配色避让逻辑
- **预设**：纯写入操作（批量 `setGlobalField`），不引入新的存储形态

### 兼容性

- 浏览器需支持 CSS `color-mix()`（既有要求不变）；`@keyframes` 中引用 `var()` 需 Chromium 111+/Firefox 113+/Safari 16.2+，与 `color-mix` 基线一致
- `useSessionStatus` 缺失（未来宿主裁剪）时自动跳过状态规则，其余功能不受影响
- DSH 版本范围维持 `>=0.2.2-rc.5 <0.3.0`

## 风险与回退

- **状态 hook 行为差异**：`running` 可能为 `undefined`（基线未建立），按「不 running」处理，不误亮
- **规则数量增长**：状态着色使规则数 ≈ 会话数 ×1.5，百级会话下仍是几百行 CSS，注入成本可忽略
- **回退**：所有新键均有默认值，清空 localStorage 即回出厂；插件停用即完全恢复原貌
